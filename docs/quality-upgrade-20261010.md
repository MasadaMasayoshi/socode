# 品質改善 — 2026-10-10

作業ブランチ: `review/nursing-classification-stage1`。公開版への反映は未実施。

## 実装した改善

- 充足判定のキャッシュは本文の長さではなく、本文・日時・分類・対象時期・除外状態の変更で更新する。同じ文字数で SpO2 98% → 88% と変更しても古い判定を表示しない。
- 看護問題の現在所見に入院前だけの記録を戻さない。計画内の根拠文章だけでは現在の問題を成立させず、現在のカードとの一致を確認する。
- 削除済み・AI提案のカードを充足判定と計画の観察根拠から除外する。
- 新しい計画では、完全一致が一意に定まる根拠カードに限ってIDを連携し、本文・日時・分類・時期のスナップショットを保存する。曖昧な一致からIDを作らない。
- 根拠の変更・削除・除外を継続して警告する。新しい計画の警告は再読込後も保存した根拠との比較から再検出できる。
- 計画の根拠変更を画面で表示し、変更前と現在の内容を確認して更新できる。確認中の変更を検出して中止する。根拠の更新履歴を最大20件保存し、目標・OP/TP/EPを見直すよう表示する。
- 保存済みの計画検証結果を無条件に再利用せず、現在の記録で再評価する。
- 自動品質チェックは既存の「タグ不要」「基本情報」ルールを利用し、未分類の理由を表示する。
- OP/TP/EP内の完全一致する内容の重複、推論を含む因果矢印の根拠不足、関連図と計画の問題名の不一致を点検する。結果は確認候補で、診断・分類を自動変更しない。
- 同じ観察でも日時・種別・入院時期が違うカードは重複扱いにしない。
- 本文のUndo/Redoは患者ごとに分離し、患者を往復しても別の患者のRedoを破棄しない。後から編集した本文は上書きしない。
- テストの対象ファイルを明示し、簡易テストスクリプトの再帰実行を防ぐ。Windowsでもシェルのワイルドカード展開を必要としない。
- 簡易テストは既知の失敗も失敗として返す。不正な対象・中断・出力不足でも成功扱いにしない。プロキシ利用環境ではテスト用localhostだけを迂回する。

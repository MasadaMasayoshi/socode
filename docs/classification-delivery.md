# Classification backup and mail

Completed classification first calls the existing local/shared save, then captures the same credential-free JSON schema as the Save button. That JSON and a full correction-request TXT become two attachments addressed exclusively to the owner's specified Gmail address. Both correction exports now instruct multi-perspective untagged review followed by collection of similar evidence and additional domains on already-tagged cards, using attached source only.

The durable browser outbox captures each run's content before later edits, retries on load/online and after transient failures, and removes an entry only after the backend confirms the same delivery ID. Delivery status has no in-site toast, banner, dialog or notification. The existing classification-complete message remains unchanged. Pending jobs consume local storage; if that storage cannot accept another backup, the current in-memory attempt still runs and developer diagnostics record the failure.

The backend persists the complete backup privately before SMTP and records confirmed acceptance. Requests cannot choose the recipient, attachment paths, remote URLs or transport settings. Known completed IDs deduplicate concurrent requests, HTTP retries and server reloads. SMTP cannot guarantee exactly-once delivery if the process dies after remote acceptance but before recording it. SMTP acceptance also does not prove inbox arrival. The directory is blocked from static serving; its contents are not tracked or included in Pages releases.

Configure the running backend environment using the SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS and SMTP_FROM names in .env.example. Set credentials directly in the backend host's environment; do not share them in chat or source control. Enable a persistent NURSING_DATA_DIR for server-side retained backups. Gmail SMTP requires sender credentials supported by the sending account, independently of the recipient address. Restore a stopped backend before relying on automatic mail. GitHub Pages only hosts the client; it does not send SMTP mail.

Missing settings or failed delivery return a retryable failure, retain the private saved job and keep the client copy queued. No real message is sent in unit/browser tests. Unit tests inject a fake transport and verify fixed recipient, UTF-8 attachments, persistence-before-send, deduplication, retry, input validation, absence of credentials, protection of captured content and absence of UI notifications. Browser checks intercept only the delivery transport and exercise the real classification button at three widths. Live configured SMTP/inbox delivery remains unverified until backend configuration is available.

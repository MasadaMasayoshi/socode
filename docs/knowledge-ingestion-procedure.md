# 知識取り込みの手順（毎回これで再現する）

深層調査の回答を、サイトの知識に取り込むための手順書。コードは書かない。場所と順番だけを決める。

## 1. 流れ

1. 知識リクエストを書き出す（サイトの「知識をリクエスト」。個人情報は自動で匿名化される）。
2. 調査の回答を、そのまま `docs/research-notes/日付-名前.md` に保存する（原文を削らない。後で取り込み直せるようにする）。
3. 回答の各節を、下の「3. 対応表」の場所へ振り分ける。
4. 方針（5.）を守って書く。
5. 検証（6.）を行い、版を上げる。
6. 台帳に行を足し、この文書の末尾に「取りこぼし確認表」を付ける。

## 2. 方針

- 出典がなくても、見送らない。出典欄は「深層調査 日付（出典未確認）」か調査メモのパスにする。
- 症例の名前・値に合わせたルールを書かない（一般化した語だけ）。
- 言い方は条件付きにする（「〜することがある」「〜の可能性」）。断定や診断をしない。
- 全ての新しい行に、出典・版・確認日・次回見直し日を付ける。
- 14項目は1つに決めず、複数付ける（多値）。薬剤名は項目に直接貼らず、「作用→有害事象→観察項目→14項目」の順に結ぶ。
- 否定（〜なし）・既往（陳旧性など）・時制（術後・予定・抜去済み）は、警告を出す前に除く。確定・疑い・リスクを区別する。
- 未知語は置き換えず、知識リクエストに出して人が確認する。

## 3. 回答の節 → 場所

| 回答の節 | 入れる場所 |
|---|---|
| 疾患・薬・症状ごとの観察・援助・教育（OP/TP/EP） | `js/12` の `CARE_PLAN_KNOWLEDGE`（行ごとに、きっかけの語、OP/TP/EPの要点と各要点の確認語、出典、版、確認日、次回見直し日） |
| 症状・疾患 → 14項目 | `js/07` の `DISEASE_SYMPTOM_NEEDS`（先に既存のキーワードで付くか確認し、足りない語・複数付ける語だけ足す） |
| 原因 → 途中 → 結果 | `js/15` の `RM_BRIDGE_RULES`（条件付きの言い方で） |
| 高リスクの組合せ | `js/12` の `CP_HIGH_RISK_COMBOS`（全部の語が揃ったときだけ。参考扱い） |
| 標準用語でない語 | `js/12` の `KR_UNKNOWN_TERMS` / `krUnknownTerms`（知識リクエストの画面に出る） |
| 検査値の読み方 | `js/08` の検査評価の考察（`buildLabAssessment`）。文脈のつながりだけを足す |
| 共通の看護問題 | 行（`CARE_PLAN_KNOWLEDGE`）と鎖（`RM_BRIDGE_RULES`）の両方 |
| 周術期の時期 | 行（出来事で区切る。日数を固定しない） |
| 設計の提案 | 否定・既往の除外（`cpStripNegated`）、確定／疑い／リスク（`cpEvidenceKind`）、出典の項目、台帳 |
| 見送り・範囲外の理由 | 台帳の行（理由を書く） |

## 4. 台帳

`docs/knowledge-guideline.md` の台帳に、1回の取り込みにつき複数行を足す（日付・知識・種類・理由・出典・効く場所・見直し予定）。

## 5. 書くときの確認

- きっかけの語が広すぎて、無関係な記録で出ていないか。
- 既存の語と二重になっていないか（先に検索する）。
- 症例固有の語が入っていないか。
